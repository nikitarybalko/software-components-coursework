## Передумови

Сесію ініціалізовано (`POST /api/v1/simulation/init`), симулятор Blue зареєстровано.

## Кроки відтворення

1. Надіслати `POST /api/v1/simulation/ticks/submit` з ключем `blue-secret-token`.
2. У тілі передати юніт зі значенням `"status": "BROKEN"`, якого немає в переліку `UnitStatus`.

## Очікуваний результат

Відповідь 400 Bad Request з описом, яке поле має недопустиме значення. Помилка клієнта фіксується як VALIDATION_ERROR.

## Фактичний результат

Відповідь 500 Internal Server Error з повідомленням «An unexpected server error occurred». Клієнт не дізнається, що саме не так у запиті, а в журналі сервера помилка клієнта записана як збій сервера (рівень ERROR).

## Вкладення

[attachments/BR-01-server-error.txt](attachments/BR-01-server-error.txt) — відповідь API і лог брокера, отримані повторним відтворенням 16.11.2026 на коміті c2d8df4.

## Причина

Jackson кидає `HttpMessageNotReadableException`, якщо JSON не вдається прочитати. `GlobalExceptionHandler` не мав окремого обробника для цього винятку, тому спрацьовував загальний обробник `Exception.class`, який повертає 500.

## Виправлення

Додано обробник `HttpMessageNotReadableException`, що повертає 400 з описом причини й записує подію VALIDATION_ERROR.

## Регресійна перевірка

- `TickControllerTest#submitUnitsWithUnsupportedTypeReturnsBadRequest`
