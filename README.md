# Мікросервіс для обміну даними між симуляторами (Варгейм)

> **Курсова робота** з дисципліни **«Компоненти програмної інженерії»**
> **Тема роботи №12:** Мікросервіс для обміну даними між симуляторами.

---

## 1. Загальний опис проєкту

Даний проєкт є серверним брокером (REST API) для тактичного варгейму (агентного моделювання бойових дій на базі архітектури типу *Project Mesa*). Мікросервіс виступає незалежним арбітром часу та координатором між двома автономними симуляторами протиборчих сторін (**Blue Force** та **Red Force**), а також веб-панеллю оперативного спостереження (**Дашборд Командира**).

## 4. Запуск

Потрібні лише Docker і Docker Compose. Мікросервіс і PostgreSQL піднімаються однією командою:

```bash
docker compose up -d --build
```

- Дашборд Командира: http://localhost:3000
- Swagger UI: http://localhost:8080/swagger-ui.html
- Контейнер мікросервісу обмежено 512 MB RAM (JVM використовує до 75% ліміту), PostgreSQL і дашборд обмежено по 256 MB.

Демонстраційний прогін Mesa-симуляторів (Blue та Red Force) проти запущеного брокера:

```bash
docker compose --profile demo run --rm simulators --url=http://backend:8080 --ticks=30
```

Параметр `--seed=42` робить бій відтворюваним: з тим самим seed юніти рухаються й зазнають втрат однаково при кожному запуску. Blue використовує seed, Red використовує seed + 1.

Зупинка зі збереженням даних БД: `docker compose down`. Повне очищення разом із томом БД: `docker compose down -v`.

### Тести

```bash
cd backend && ./mvnw test
```

Потрібен запущений Docker: інтеграційні тести піднімають PostgreSQL 16 через Testcontainers.

| Рівень | Інструменти | Що покриває |
| :--- | :--- | :--- |
| Unit | JUnit 5 + Mockito | Туман війни, `UnitState`, бар'єрна синхронізація тіків, життєвий цикл сесії |
| Web slice | `@WebMvcTest` + MockMvc | контролери, валідація, API-ключі та ролі, коди помилок |
| Інтеграційні | `@SpringBootTest` / `@DataJpaTest` + Testcontainers | повний цикл REST → ядро → PostgreSQL, snapshot'и, журнал подій, Reset, відновлення зі snapshot'а |
| Конфігураційні | JUnit 5 + SnakeYAML | версії Java і Spring Boot, сервіси та ліміти пам'яті в docker-compose, налаштування PostgreSQL |

### Дашборд Командира

- **Поле бою.** Юніти позначено за NATO APP-6: рамка показує сторону (Blue прямокутник, Red ромб), зображення всередині показує тип (танк, колісний БТР, солдат, бінокль для розвідки), смуга під символом показує стан (жовта для пошкодженого, червона для знищеного). Карта оформлена як штабний аркуш фіксованого розміру 300 × 200: квадрати сітки A1…, масштабна лінійка та стрілка півночі на полях, у режимах сторін ділянки поза оглядом заштриховано.
- **Масштаб.** Кнопки «+», «−», «Усі юніти» (підігнати під район бою) і «Уся карта»; Ctrl + коліщатко або жест зведення на тачпаді; перетягування зсуває збільшену карту. Символи при збільшенні ростуть повільніше за карту, тому скупчення розходяться, а мітки квадратів і масштабна лінійка перераховуються під видиму ділянку. Видно зони огляду з урахуванням стану юніта (радіус розраховує брокер), сліди руху та позначки «виявлений противником».
- **Режими перегляду.** «Арбітр» показує повну картину. «Очима Blue» та «Очима Red» показують лише те, що брокер повертає відповідному симулятору, а решта поля прихована туманом війни.
- **Керування.** Ініціалізація, пауза з причиною, продовження, скидання, відновлення з будь-якого snapshot'а. Небезпечні дії потребують повторного натискання.
- **Моніторинг.** Тік і статус сесії, реєстрація симуляторів та хто вже надіслав хід, зведення сил сторін, журнал подій.

Адмінський ключ лишається на сервері. Браузер звертається до `/api/simulation/*` самого дашборда, а Next.js проксіює запит до брокера з `WARGAME_ADMIN_API_KEY`. Для локальної розробки:

```bash
cd frontend && cp .env.example .env.local && npm install && npm run dev
```

### API-ключі (заголовок `X-API-KEY`)

| Ключ за замовчуванням | Роль | Доступ |
| :--- | :--- | :--- |
| `blue-secret-token` | Blue Force | реєстрація симулятора, відправка своїх юнітів, свій Туман війни, статус |
| `red-secret-token` | Red Force | те саме для Red Force |
| `admin-secret-token` | Адміністратор | керування життєвим циклом (init, pause, resume, reset, restore), повна картина поля бою, snapshot'и, журнал подій |

Ключі перевизначаються змінними середовища `WARGAME_BLUE_API_KEY`, `WARGAME_RED_API_KEY`, `WARGAME_ADMIN_API_KEY`.

### Типи підрозділів

Кожен юніт має тип (`unitType`): `ARMOR`, `MECHANIZED_INFANTRY`, `INFANTRY`, `RECON` або `UNKNOWN`, якщо тип не вказано. Брокер тип перевіряє, зберігає у snapshot'ах і передає далі, а характеристики типів задають симулятори ([simulators/unit_profiles.py](simulators/unit_profiles.py)):

| Тип | Огляд | Швидкість | Дальність ураження | Влучність за тік | Захист | Дистанція бою |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| Танковий | 60 | 3.8 | 25 | 12% | 50% | 21 |
| Механізована піхота | 55 | 4.2 | 18 | 8% | 30% | 15 |
| Піхота | 50 | 2.5 | 15 | 7% | 0% | 12 |
| Розвідка | 85 | 5.5 | 12 | 3% | 10% | 45 |

Кожен живий ворог, у дальності ураження якого опинився юніт, раз на тік стріляє по ньому. Шанс влучання дорівнює влучності ворога (у пошкодженого вдвічі менше), зменшеній на захист цілі. Перше влучання пошкоджує юніт, друге знищує. Боєздатний юніт тримається на своїй дистанції бою від найближчого ворога, тому розвідка спостерігає здалеку й не вступає в бій. Пошкоджений юніт рухається вдвічі повільніше і відходить за межу дальності ураження найближчого ворога.

### Порядок роботи симулятора

1. `POST /api/v1/simulators/register`: реєстрація сторони (без неї відправка юнітів повертає 409).
2. Адміністратор викликає `POST /api/v1/simulation/init`.
3. Кожен тік: `POST /api/v1/simulation/ticks/submit`, потім опитування `GET /api/v1/simulation/ticks/{tick}/fog-of-war`. Поки суперник не відправив свій хід, endpoint повертає 409.
4. Якщо жодна зі сторін не відповідає довше за тайм-аут (10 с), симуляція автоматично переходить у `PAUSED`.
5. Статус містить `epoch`, який збільшується після кожних init, reset і відновлення зі snapshot'а. Побачивши нове значення, симулятор запитує `GET /api/v1/simulation/ticks/current/units` і замінює свої локальні юніти відповіддю брокера. Порожній список означає новий бій: юніти повертаються на стартові позиції.
